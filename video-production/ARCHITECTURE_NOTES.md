# Architecture notes for the video

The diagram at 0:12–0:35 shows only components that exist in the code. This file records each box, where it lives, and the decision behind it.

| Box in the diagram | Code | Problem → choice → benefit → where it shows in the video |
|---|---|---|
| Request (inline ⌘⌥K / agent panel) | `src/extension.ts` `inlineEdit()`, `src/ui/sidebar.ts`, `media/forge.js` | **Problem:** edits should start where the code is. **Choice:** stay editor-native (keybinding plus a sidebar), with no chat-and-copy. **Benefit:** the result is a diff, not text. **Shown:** Task A 0:35, Task B 1:16 |
| Context pack before any model call | `src/agent/retrieval.ts` `assembleContext()`, `src/repoMap.ts`, `src/core/profiles.ts` | **Problem:** Flask is larger than a free model can usefully take, and a search-read loop burns calls. **Choice:** a deterministic ranked pack (BM25 terms, path, RepoMap symbol rank and neighbours, module affinity, @mentions) under a token budget (7k standard, 2.2k for rate-limited providers), with a reason for each file. **Benefit:** the model starts in the right files. Task B used 4.8k of 7.0k tokens. **Shown:** 1:38–1:48 (context card); 2:42 (the same pack in TrueForge's first turn) |
| TrueForge (local): sessions, turns, events | `src/core/session.ts` `runSession()`, `src/core/trueforge.ts` | **Problem:** a hand-built agent loop means rebuilding streaming, history and approvals. **Choice:** TrueForge runs the loop; the extension creates sessions and turns through the TypeScript SDK and renders the streamed events. **Benefit:** fewer moving parts; the session can be inspected. **Shown:** session link in every run card; session page 2:41–2:51 |
| Tool calls & tool approval | `requireApprovalForTools: ["submit_for_review"]` / `["propose_edit"]`; `tool.approval_required` → `onApproval` → review → `user.tool_approval` | **Problem:** the agent must not write files on its own. **Choice:** writing is an approval-gated tool, and the approval *is* the per-hunk review. **Benefit:** no silent writes; TrueForge's record shows the decision ("The user accepted 4 hunk(s)…"). **Shown:** 2:48 |
| Compaction · deferred tool loading | `buildAgentSpec()`: `compaction.trigger.input_tokens` (18k standard), `preload: false` + `preloadTools` (5 of 9 tools) | **Problem:** long runs overflow small context windows, and tool schemas cost tokens on every request. **Choice:** use TrueForge's own context-engineering features. **Benefit:** fewer tokens per request. **Shown:** "TrueForge list_tools · deferred tool loading" rows 1:48–1:53 and 2:46 |
| Any model | Models come from TrueForge `/models`; the extension has no provider code | **Problem:** the competition requires model independence. **Choice:** the model picker lists what TrueForge has. **Benefit:** a judge can swap models in TrueForge. **Shown:** Gemini, OpenRouter, and a broken custom endpoint in one video |
| MCP tools (loopback) | `src/agent/tools.ts`, `src/workspaceMcp.ts` (Streamable HTTP on 127.0.0.1, random path) | **Problem:** the agent, not the extension, must decide what to read and change. **Choice:** 9 batched tools; `stage_edits` only stages in memory; `run_command` runs in a sandboxed snapshot. **Benefit:** the workspace is untouched until approval. **Shown:** timeline rows; `git status` clean before Accept in Task C |
| Per-hunk review → apply → Undo | `src/review/reviewController.ts` | **Problem:** users need fine-grained control and a way back. **Choice:** one diff tab per file; per-hunk checkboxes plus in-diff CodeLens; base text re-checked at apply time; one `WorkspaceEdit`; Undo only if the files are unchanged since. **Benefit:** no half-applied or clobbered edits. **Shown:** 0:51 (untick), 1:53 (CodeLens "✓ Accept Hunk 4/4 \| ✕ Reject"), 2:30 (Undo) |
| Model router | `src/core/router.ts` | **Problem:** free providers fail constantly. **Choice:**<br>• network/5xx → backoff 2 s, then 4 s<br>• 429 → wait up to 65 s<br>• credential, quota or availability failures → switch to the next listed model via `sessions.update(spec)` in the **same session**<br>**Benefit:** runs survive outages. **Shown:** Task C 3:06–3:13; Task B's four-model chain |

## What is not claimed

- **No custom orchestration graph or state machine.** The loop is TrueForge's. The "graph" is RepoMap's code graph inside the context pack.
- **TrueForge has no built-in fallback (0.185.1).** The policy lives in Forge; every model call still goes through TrueForge.
- **Not used:** subagents, skills, Code Mode (off by default), web search.
