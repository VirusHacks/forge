Forge reads a repository larger than the model's context window, changes the files the user never named, tests its own work, and shows every hunk for review before anything touches disk — and keeps going when the model fails. It is built to work on free-tier models, so every design choice aims at fewer, smaller, safer requests.

3. Architecture on TrueForge

In short: the extension is a client of a local TrueForge agent. It opens sessions and turns with the TypeScript SDK and renders the streamed events; the editor's abilities are MCP tools, so the agent decides what to read, change and run. TrueForge makes every model call.

One request, step by step

1Context pack

BM25 + RepoMap graph choose files and whole functions under a token budget — no model call.

2Agent loop

TrueForge runs the model; it calls Forge's MCP tools: search_code, read_code, find_symbol, stage_edits, run_command.

3Stage + verify

Edits stay in memory; Forge runs the relevant tests in a sandboxed copy and reports only new failures.

4Approval = review

submit_for_review needs TrueForge approval; that request opens the diff with Accept / Reject on every hunk.

5Apply · Undo

Accepted hunks are applied and saved; files changed meanwhile are refused; Undo restores them.

4. How context is selected

In short: a budgeted pack built from text ranking and the code graph, shown to the user file by file with the reason it was chosen.

  1. Rank text with BM25 over lines (length-normalised); boost files that define a named identifier; words like "test" or "documented" pick file roles.
  2. Add the code graph. RepoMap's focus symbol must sit in the best text-ranked file. Its callers, callees and tests join — and each caller edge is checked against its call-site line.
  3. Pick by role: best implementation, test and docs file; extra files need graph or naming evidence, not just shared words.
  4. Excerpt whole functions using RepoMap's parsed symbol ranges, plus an outline, until the budget is used.

7. Tools used

  • AI coding assistants: Claude Code (Anthropic) and OpenAI Codex.
  • Harness: TrueForge 0.185.1 (local) with its TypeScript SDK; MCP TypeScript SDK; RepoMap 1.9.0.
  • Editor and tests: VS Code Extension API; 8 tests in a real VS Code; 21 offline tests including a fake TrueForge; pytest; uv; macOS sandbox-exec.

8. Known limitations — and another month

  • Free tiers are the ceiling. Of five live Task B runs through the extension, two passed every check, one made a wrong change (which led to our duplicate guard and quality gates), and two stopped when Gemini and Groq were exhausted at the same time — the partial work was offered for review, flagged as incomplete.
  • Weak free models make many small calls: Task B takes 20–40 calls.
  • The code graph is static analysis: we verify each edge at its call site, but dynamic calls can still be missed.
  • The command sandbox is macOS-only; Linux uses a throwaway copy without OS isolation; Windows is untested.

Another month: persistent indexes for very large repos; prefetching to cut calls; Linux sandboxing; an evaluation suite to tune ranking; TrueForge PRs for built-in model fallback and the reasoning_content bug that breaks gpt-oss-20b on Groq.
