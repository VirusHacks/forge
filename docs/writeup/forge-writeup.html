Forge reads a repository larger than the model's context window, changes several files the user never named, tests its own work, and shows every hunk for review before anything touches disk — and keeps working when the model behind it fails. We built it to succeed on free-tier models, where per-minute token limits make every request count, so each design choice below trades complexity for fewer, smaller, safer requests.

3. Architecture on TrueForge

Figure 1. Four layers. The extension is a client of a local TrueForge agent: it creates sessions and turns through the TypeScript SDK and renders the streamed events. Editor capabilities are MCP tools, so the agent — not the extension — decides what to read, change and run. Every model call is made by TrueForge.

Design decisions and trade-offs

DecisionAlternative we rejectedWhy — with what we measured
Context pack before the first calllet the agent navigate with search/readv1 spent 40–85 model calls exploring; each call re-sends the history. With the pack, Task A needs 2 calls and Task B ~29.
Batched MCP toolsTrueForge Code Mode (local sandbox)Code Mode raised per-request harness tokens from 213 to 1,978 — about 3× fewer requests per minute on Groq's 7k-TPM free tier. Kept opt-in (forge.codeMode).
Same-session fallbackrestart a new session / checkpoint filesKeeps every tool result; replaced v1's checkpoint machinery. Needs inline-spec sessions: named-agent sessions return 422 agent cannot be updated.
Harness runs the testsrely on the model to call testsZero model calls, results diffed against an unmodified baseline so only new failures count. Caught a broken model test in Task B.
Stage in memory, write on approvalwrite to disk, revert on rejectCancellation is trivially consistent; files are re-read at apply time and never overwritten if they changed during review.
Budget profiles per providerone global budgetGroq rejects any single request above ~7k tokens; "tight" providers get a 2.2k pack and 1k output, others 7k.
Gates that fire oncehard requirementsWeak models submit early; each gate (failing tests, missing tests/docs, unverified) refuses one submit with a reason but never traps the agent.

4. How context is selected

  1. Terms & role intent. Identifier-aware terms; "test", "documented" select file roles instead of being searched.
  2. BM25 over lines, length-normalised, boosted for files that define a named identifier, filename matches and co-occurring terms; changelogs penalised.
  3. RepoMap code graph. Focus = the RepoMap symbol inside the best BM25 implementation file, so text and graph must agree; its callers, callees and tests join with reasons.
  4. Role selection. Best implementation, test and docs file; any further file needs structural evidence (graph neighbour, defines an identifier, named after the module, @-mentioned) — shared words are not enough.
  5. Whole-symbol excerpts ranked by term density, plus outlines with line ranges, packed under the budget; @file/@symbol always win.

Where: provider APIs, called only by the local TrueForge server. Cost: $0 — every model is a free tier.

Switching models: pick any TrueForge model in the sidebar; list automatic fallbacks in forge.fallbackModels. Nothing is provider-specific except an optional "tight budget" list. Keys live only in TrueForge; the repository ships model-providers.example.json with placeholders.

Router policy: 429 with Retry-After ≤ 65 s → wait; 5xx / network → exponential backoff (2 s, 4 s); malformed tool call → one retry; bad credentials / quota / unavailable / too large → switch. Credentials block the provider; quotas only the model.

8. Known limitations — and another month

  • Free tiers are the ceiling. Of five live Task B runs through the extension, two passed every check; one produced a wrong change (which led to the duplicate guard and gates); two stopped when Gemini (503) and Groq (per-minute limits) were exhausted at once — Forge offered the partial staged work for review instead of losing it, flagged as incomplete.
  • Weak free models make many single calls: Task B takes 20–40 calls despite batching guidance.
  • Sandbox is macOS sandbox-exec; Linux has a throwaway copy without OS isolation; Windows untested.
  • Outline is pattern-based; RepoMap edges are static inferences. Hunk decisions live in the sidebar, not inside the diff editor. Sidebar history is per window.

With another month: persistent RepoMap/BM25 indexes for very large repos; plan-then-fetch prefetching; in-editor hunk controls; bubblewrap sandbox on Linux; an evaluation suite to tune ranking by measured success; upstream TrueForge PRs for built-in model fallback, agent switching on named sessions, and the reasoning_content echo that breaks gpt-oss-20b on Groq.
